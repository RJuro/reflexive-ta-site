# P10.2 — SYNTHESIZE, the loop mechanisms, and the API contract

*2026-08-29. The contract both the engine build and the frontend build work against, so they
can proceed in parallel. Design reference: `design/agent-workbench/masshine-research-workbench.html`
(ideas, not pixels — it is deliberately more cluttered than we ship). System model:
`design/MASSHINE.md` §2.*

## 1. What this phase adds

The loop architecture stops being a document and becomes machinery:

| mechanism | what it is | where it shows |
|---|---|---|
| **SYNTHESIZE** | one call per document after READ → findings, walkthrough steps, intro, story | Session, Journal |
| **Focus versioning** | the research question as a versioned object; researcher edits, machine may propose | Home, Journal |
| **Check-back** | every standing researcher steer re-tested against the material each synthesis | Session step, Needs judgment |
| **Residue** | passages/codes nothing above claims — surfaced, with an abductive reframe offer | Journal "Doesn't fit yet" |
| **Needs judgment** | derived queue of *exceptions only* — never clerical work | right rail, everywhere |

## 2. Schema (project DB unless noted; guarded ALTERs / new tables, forward-only)

- `focus_version(id INTEGER PK, n INT, text TEXT, author TEXT /* researcher|assistant */,
  status TEXT /* active|superseded|proposed|declined */, rationale TEXT, created_at)`
  — the active row is the current focus. Registry `project.research_question` stays as a
  cached mirror of the active text (existing readers keep working).
- `finding_state(theme_id TEXT PK, mode TEXT, standing TEXT, standing_note TEXT,
  stance TEXT, opened_evidence TEXT /* JSON list of sid */, updated_at)`
  — `standing` is COMPUTED, never a researcher input; `stance` is rolled up from reactions.
- `step(id, mode, doc_id, position, kind, payload JSON, reaction TEXT, reaction_note TEXT,
  created_at)` — walkthrough steps, replayable; `kind ∈ pattern|tension|uncertainty|delta|
  declined|checkback|residue`.
- `story_version(id, n, text JSON /* [{para, sids[]}] */, created_at)`.
- `intro(doc_id PK, text JSON /* [{para, sids[]}] */, created_at)`.

## 3. SYNTHESIZE

One call per document after READ. **Input:** transcript, this doc's codes+evidence, current
findings with their support, active focus + its version history, story-so-far, standing
researcher steers (reactions, reframes, challenges from `compile_guidance`), and the
previously-declined material (so a focus shift can re-offer it).

**Output** (Python-validated; every sid must resolve, every code/finding id must exist,
failures dropped and counted):

```json
{"findings":[{"id":"T01","central_concept":"...","label":"...","supporting_code_ids":[...],
              "key_evidence_sentence_ids":[...],"tensions":[...]}],
 "steps":[{"kind":"pattern","statement":"...","sids":[...],"code_ids":[...],
           "weakest_sids":[...],"finding_id":"T01"}],
 "checkbacks":[{"steer":"<the researcher's own words>","target":"T02",
                "supports":{"text":"...","sids":[...]},
                "strains":{"text":"...","sids":[...]},
                "not_found":{"text":"..."},
                "proposal":"<one concrete revision, or empty>"}],
 "residue":[{"note":"...","sids":[...],"code_ids":[...],"reframe_offer":"..."}],
 "intro":[{"para":"...","sids":[...]}],
 "story":[{"para":"...","sids":[...]}],
 "focus_proposal":{"text":"...","rationale":"..."}   // or null
}
```

**Standing is computed in Python, never asked of the model:** `firm` (≥2 documents and ≥N
supporting codes), `single-case`, `thin` (below threshold). `standing_note` is generated from
counts. Reason: standing is an evidential fact, and the model is not allowed to grade its own
support.

## 4. Endpoints

```
POST /projects/{pid}/synthesize     {mode?, model_id?} → job
GET  /projects/{pid}/session/{doc_id}
     → {intro:[{para,sids}], steps:[{id,kind,statement,sids,code_ids,weakest_sids,
        finding_id,reaction,reaction_note, checkback?:{steer,supports,strains,not_found,proposal}}],
        n_steps, doc:{id,title}}
POST /projects/{pid}/steps/{step_id}/react   {reaction: agree|challenge|reframe|park,
                                              note?, statement?} → {ok, step}
GET  /projects/{pid}/journal
     → {focus:{active:{n,text,author}, history:[...], proposal:{n,text,rationale}|null},
        story:{n, paras:[{para,sids}], versions:[n...]},
        findings:[{id,label,central_concept,standing,standing_note,stance,
                   supporting_code_ids,key_evidence_sentence_ids,opened_evidence,
                   evidence_opened_count,evidence_total}],
        residue:[{note,sids,code_ids,reframe_offer}],
        memos:[...], history:[{kind,label,at,restorable}]}
GET  /projects/{pid}/needs-judgment
     → {items:[{kind,title,detail,target_type,target_id,action_hint}], count}
       kinds: checkback | strained_finding | focus_proposal | residue | audio_review | thin_finding
POST /projects/{pid}/focus     {text}                  → new researcher version (active)
POST /projects/{pid}/focus/proposal/{n}  {accept|decline} → adopt or decline machine proposal
POST /projects/{pid}/findings/{tid}/evidence-opened  {sid} → records a gate visit
POST /projects/{pid}/residue/{idx}/reframe   {}        → queues a reframe read (guidance only)
```

Existing endpoints unchanged. `model_id` accepted wherever jobs start (P10.1c).

## 5. Rules that must survive implementation

1. **Standing computed, stance recorded, verdicts only at review.** No endpoint accepts a
   researcher-set standing.
2. **The check-back is not optional flattery.** If the material does not support a steer, the
   `strains`/`not_found` fields must say so; a checkback with all three empty is dropped as
   invalid by the validator.
3. **Residue is never auto-resolved.** The reframe offer is a proposal; only a researcher
   action turns it into guidance.
4. **Needs judgment surfaces exceptions only** — never "N codes to review". If it can be
   handled automatically, it does not belong there.
5. **Declined material is re-offered** when the focus changes: READ receives the active focus
   and the parked declines each run.
6. Everything is grounded: any sid that does not resolve is dropped before persistence.
